# Version 4.10.4 Update (SQLite WAL Locks)

## Improvements & Bugfixes
- **Fixed Silent Database Locks**: Resolved an issue where commands were silently failing to write to the `command_history` table due to SQLite "database is locked" errors. This occurred because `go-sqlite3`'s `_busy_timeout` was not set, causing concurrent writes in WAL mode (such as writing raw chunk data vs history data) to instantly abort instead of waiting. The connection string now specifies `_busy_timeout=5000`. Additionally, insertion failures are now logged to `stderr` instead of being swallowed silently.
- **Bug tracking**: Resolved according to the specifications in `docs/bugs/sqlite-wal-lock.md`.
