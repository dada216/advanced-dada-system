# Version 5.0.0 (Quokka)

## Major Enhancements & Design Choices

Welcome to the **v5.0.0 (Quokka)** release of the Advanced Dada System! This major version bump consolidates the significant architectural improvements and stability hardening accomplished throughout the v4.x series, specifically focusing on data integrity, correct shell integrations, and foundational testing reliability.

### 1. Robust Unit Test Framework Integration
In previous versions, the codebase relied almost exclusively on end-to-end integration tests (`integration.sh`), leaving the internal logic layers uninstrumented by standard Go testing tools.
- We have introduced native Go unit tests for our core packages: `internal/meta`, `internal/config`, and `internal/sessiondb`.
- Mocked host environments (such as simulated `XDG_DATA_HOME` paths and in-memory SQLite paths) allow for clean, isolated database testing.
- Unit test coverage for core business logic has more than doubled, increasing total system coverage from 17% to 37% (with CLI/Orchestrator layers intentionally deferred to integration tests).

### 2. Bulletproof Zsh Support (ZLE Compatibility)
We successfully resolved the notorious Zsh Line Editor (ZLE) syntax-highlighting bugs.
- **The Issue:** ZLE plugins (like `zsh-syntax-highlighting` or `zsh-autosuggestions`) frequently send terminal redraw (`\r` and ANSI clear) sequences. In earlier versions, `ads-shell` attempted to extract command history by snooping raw PTY keystrokes between prompt markers, which failed entirely when the prompt was wiped and redrawn.
- **The Solution:** We decoupled command extraction from the PTY entirely. The `_ads_preexec` hook now natively injects the exact executed command string directly into the OSC 133 `C` marker payload (`printf "\033]133;C;%s\007" "$1"`). The internal ANSI state machine was updated to parse this exact payload, rendering the history recording 100% immune to visual terminal redraws.

### 3. SQLite WAL Concurrency
- Fixed a silent failure bug where `command_history` rows were dropped due to SQLite `database is locked` errors.
- **The Solution:** Because we utilize `_journal_mode=WAL` to allow rapid stream writes alongside history indexing, we required a busy timeout to safely queue concurrent transactions. We have injected `_busy_timeout=5000` into the SQLite connection string, ensuring that background stream writers do not block synchronous prompt hooks from saving correctly.

## Architecture Refinements
The transition to explicit OSC payloads over PTY scraping cements our long-term strategy of relying heavily on semantic shell hooks rather than fragile terminal emulation heuristics. This ensures compatibility across an expanding matrix of multiplexers (Konsole, Tmux) and shells (Bash, Zsh).
