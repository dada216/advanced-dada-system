# v0.2 Implementation Plan: Advanced Dada System (ADS)

**Scope:** Remote execution using native `ssh` integration.

---

## What v0.2 Delivers

| Command | Behavior |
|---|---|
| `ads new --remote <name>` | Create session marked as `remote`, prompt for SSH configuration (`user@host:port`), and save to `meta.db`. |
| `ads run <name>` | If session is `remote`, spawns `tmux` as usual but launches `ssh -t user@host` instead of a local `bash` shell. |
| `ads auth test <name>` | Tests the SSH connection natively using the user's local `ssh` agent before recording a session. |
| `ads delete <name>` | Safely deletes the session DB and unlinks it from the Meta-Database (carry-over from v0.1). |

---

## Implementation Steps

### Step 1: Update Meta-DB Schema
- Alter `meta.db` `sessions` table (via auto-migration) to include SSH configuration columns:
  - `remote_user` TEXT
  - `remote_host` TEXT
  - `remote_port` INTEGER
- Update `internal/meta/db.go` functions (`CreateSession`, `GetSessionByName`) to handle the new configuration fields.

### Step 2: Implement `ads new --remote`
- Add a `--remote` boolean flag to the `newCmd` inside `cmd/ads/main.go`.
- When triggered, prompt the user (using native standard input or `fmt.Scan`) for:
  - SSH User (default: `$USER`)
  - SSH Host (e.g., `192.168.1.50` or `server.domain.com`)
  - SSH Port (default: `22`)
- Save these settings into the newly created `sessions` row.

### Step 3: Implement `ads auth test`
- Create a new subcommand tree: `ads auth test <name>`.
- Fetches the remote config for `<name>` from the Meta DB.
- Executes `ssh -p <port> -o BatchMode=yes -o ConnectTimeout=5 <user>@<host> "echo 'SSH authentication successful'"`.
- If it fails, it prints an error instructing the user to check their `ssh-agent` or `~/.ssh/config`.

### Step 4: Refactor Orchestrator (`ads run`)
- Update `internal/orchestrator/run.go`.
- Check if `session.Type == "remote"`.
- If `local`, keep spawning `tmux new-session ... "bash"`.
- If `remote`, spawn `tmux new-session ... "ssh -t -p <port> <user>@<host>"`.
- Ensure the `pipe-pane` flawlessly records the native SSH stdout securely.

### Step 5: Implement `ads delete` (Cleanup)
- Add `ads delete <name>` command to complete the session lifecycle.
- Queries `meta.db` for the UUID.
- Unlinks (deletes) `~/.local/share/ads/sessions/<uuid>.db`.
- Deletes the row from `meta.db`.
