# ADS v4.0.0 "Pangolin" — Architecture

## 1. Executive Summary

v4.0.0 is a ground-up architectural rewrite. The system drops tmux as a
dependency, drops the HashiCorp go-plugin system, drops the concept of
managed remote sessions, and replaces the entire capture pipeline with a
transparent PTY proxy that works natively inside Konsole (or any terminal
emulator).

The result is a radically simpler system: three focused binaries, a
shared SQLite data layer, and deep KDE/Konsole integration for the
desktop experience.

**Codename: Pangolin**

---

## 2. Design Decisions (Locked)

| Decision | Choice | Rationale |
|---|---|---|
| Capture mechanism | PTY proxy (`ads-shell`) | Emulator-agnostic, captures both directions, no tmux dependency |
| Terminal emulator | Konsole (primary), any (fallback) | User's KDE/Fedora 44 desktop; PTY proxy works everywhere |
| Remote sessions | Dropped as a managed concept | User types `ssh` inside a recorded session — simpler, records the ssh command itself |
| Session persistence | None (ephemeral) | Close tab = seal session. Recording persists in SQLite. User runs tmux inside ads-shell if needed. |
| Session continuation | New session with `parent_uuid` link, separate `.db` | Clean isolation, no risk of appending to corrupted DB, easy deletion |
| Plugin architecture | Dropped | Search and LLM called directly from `ads` binary. YAGNI. |
| Konsole profile | One generic "ADS" profile with session picker | No per-session profile clutter. Picker defaults to new local shell. |
| `ads run` behavior | Background — opens Konsole tab | Falls back to foreground if no display available |
| Interactive search | Standalone `ads-tui` binary, full dashboard | Installed to `/usr/bin`, Bubbletea, right-click copy, no KDE global shortcut |
| `ads search` output | Human-readable default, `--json` flag | Pipeable into `jq` when needed |
| `ads list` display | Shows segment count + last active time | Per-session family aggregation |
| Konsole profile install | Both `make install` and `ads konsole install` | Belt and suspenders |

## 4. Binary Specifications

### 4.1 `ads` — CLI Orchestrator

The user-facing CLI. Manages sessions, profiles, search, LLM, and
Konsole integration. Built with `spf13/cobra`.

**Commands:**

| Command | Behavior |
|---|---|
| `ads new <name>` | Create session in `meta.db`, optional `--profile` flag |
| `ads run <name>` | Open Konsole tab running `ads-shell --session <uuid>`. Falls back to foreground if no display. |
| `ads list` | List all sessions with segment count, last active, profile, status |
| `ads delete <name>` | Delete session from `meta.db`, unlink all `.db` files in the family |
| `ads search <query>` | Federated FTS5 search, human-readable output. `--json` for JSON lines. |
| `ads edit <profile>` | Edit profile metadata tags interactively |
| `ads profile new <name>` | Create a new profile |
| `ads profile list` | List all profiles with metadata |
| `ads llm summarize <name>` | Summarize a session via OpenRouter |
| `ads llm ask <name> <question>` | Ask a question about a session |
| `ads llm config` | Configure OpenRouter API key and model |
| `ads hook bash` | Print OSC 133 shell integration script |
| `ads konsole install` | Write ADS Konsole profile to `~/.local/share/konsole/` |
| `ads konsole remove` | Remove ADS Konsole profile |
| `ads version` | Print version |

**No longer exists:**
- `ads auth test` — remote sessions dropped
- `ads update` — session profile changes handled by `ads edit`
- `ads plugin *` — plugin system dropped
- `ads search-interactive` — moved to `ads-tui`
- `ads profile edit-config` — tmux config management dropped

### 4.2 `ads-shell` — PTY Proxy Recorder

Minimal binary. No cobra. Two modes:

**Picker mode** (no flags):
1. Opens `meta.db`, reads recent sessions
2. Renders inline session picker (Bubbletea, not alt-screen)
3. User picks: new session, continue existing, or plain shell
4. Transitions to recording mode or execs bash directly

**Recording mode** (`--session <uuid>` or `--new <name>`):
1. Opens/creates session `.db` in WAL mode
2. Snapshots environment to `session_info` table
3. Injects shell hooks (sources OSC 133 script)
4. Allocates PTY pair
5. Forks `/bin/bash --rcfile <ads-hooks>` on slave side
6. Enters bidirectional copy loop:
   - stdin → PTY master (forwarded to bash) + `input_stream` table
   - PTY master → stdout (forwarded to Konsole) + `io_stream` table + ANSI-stripped → `fts_index`
   - OSC 133 scanner runs inline on output → `command_history` table
7. Handles `SIGWINCH` (resize inner PTY), `SIGTERM`/`SIGHUP` (clean shutdown)
8. On bash exit: flushes buffers, closes DB, updates `meta.db` status to `sealed`, exits with bash's exit code

**Flags:**
```
ads-shell                         # Picker mode
ads-shell --session <uuid>        # Record to existing session
ads-shell --new <name>            # Create + record
ads-shell --new-auto              # Auto-named session, no prompt
```

### 4.3 `ads-tui` — Interactive Dashboard

Full-screen Bubbletea application. Installed to `/usr/bin/ads-tui`.

**Tabs/Views:**

| View | Content |
|---|---|
| Sessions | List all sessions (with family grouping by `parent_uuid`), status, segment count, last active. Actions: [n]ew, [r]un, [d]elete, [enter] preview. |
| Search | Federated FTS5 search. Live-as-you-type. Results with session name, date, highlighted snippet. Right-click or [y] to copy. |
| Profiles | List/create/edit profiles and their metadata tags. |
| Settings | LLM configuration (API key, model). Konsole integration status. |

**Right-click copy:** Bubbletea supports mouse events. Right-click on a
search result → copies the snippet text to the system clipboard via
`xclip`, `xsel`, or Wayland `wl-copy`.

**Launch:** Just run `ads-tui` from any terminal. No dependency on
Konsole or ads-shell.

## 5. Data Model

### 5.1 `meta.db` — Session Index & Configuration

```sql
CREATE TABLE sessions (
    uuid       TEXT PRIMARY KEY,
    name       TEXT UNIQUE NOT NULL,
    status     TEXT NOT NULL DEFAULT 'created',
    profile    TEXT NOT NULL DEFAULT 'default',
    parent_uuid TEXT,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    sealed_at  DATETIME,
    FOREIGN KEY (parent_uuid) REFERENCES sessions(uuid)
);

CREATE TABLE profiles (
    name     TEXT PRIMARY KEY,
    customer TEXT,
    server   TEXT,
    project  TEXT
);

CREATE TABLE llm_config (
    key   TEXT PRIMARY KEY,
    value TEXT
);
```

**Notes:**
- `parent_uuid` links continuation sessions to their parent
- `sealed_at` records when the session was closed
- `llm_config` replaces the generic `plugin_configs` table
- Default profile is seeded on first `meta.Open()`

### 5.2 `<uuid>.db` — Per-Session Recording

```sql
-- Raw output bytes (for replay)
CREATE TABLE io_stream (
    id   INTEGER PRIMARY KEY,
    ts   DATETIME DEFAULT CURRENT_TIMESTAMP,
    data BLOB NOT NULL
);

-- ANSI-stripped text (for search)
CREATE VIRTUAL TABLE fts_index USING fts5(text);

-- Raw input bytes (what the user typed)
CREATE TABLE input_stream (
    id   INTEGER PRIMARY KEY,
    ts   DATETIME DEFAULT CURRENT_TIMESTAMP,
    data BLOB NOT NULL
);

-- Structured command history (from OSC 133 markers)
CREATE TABLE command_history (
    id           INTEGER PRIMARY KEY,
    command_text TEXT,
    start_ts     DATETIME,
    end_ts       DATETIME,
    exit_code    INTEGER
);

-- Profile metadata snapshot at recording start
CREATE TABLE metadata (
    customer TEXT,
    server   TEXT,
    project  TEXT,
    date     DATETIME DEFAULT CURRENT_TIMESTAMP
);

-- Environment snapshot at recording start
CREATE TABLE session_info (
    key   TEXT PRIMARY KEY,
    value TEXT
);
```

**New tables vs v3.x:**
- `input_stream` — records user keystrokes (PTY proxy sees both directions)
- `session_info` — environment snapshot (hostname, kernel, user, shell, cwd, terminal size)

## 7. Session Lifecycle

```
                    ads new "prod-debug"
                           │
                           ▼
                    ┌──────────────┐
                    │ meta.db      │
                    │ status:      │
                    │  "created"   │
                    │ parent: null │
                    └──────┬───────┘
                           │
                    ads run "prod-debug"
                           │
                           ▼
                    ┌──────────────┐
                    │ Konsole tab  │
                    │ ads-shell    │
                    │  --session   │
                    │  <uuid-1>   │
                    └──────┬───────┘
                           │
              ┌────────────▼────────────┐
              │ PTY proxy recording     │
              │ status → "running"      │
              │ <uuid-1>.db filling up  │
              └────────────┬────────────┘
                           │
                     User closes tab
                           │
                           ▼
              ┌────────────────────────┐
              │ status → "sealed"      │
              │ sealed_at = now        │
              │ <uuid-1>.db complete   │
              └────────────┬───────────┘
                           │
              Next day, user wants to continue:
                           │
              ads-shell picker → "Continue: prod-debug"
                           │
                           ▼
              ┌────────────────────────┐
              │ NEW session in meta.db │
              │ name: prod-debug-2     │
              │ parent_uuid: <uuid-1>  │
              │ uuid: <uuid-2>         │
              │ status: "created"      │
              └────────────┬───────────┘
                           │
                    (same lifecycle)
```

### Session Families

A "session family" is a chain of sessions linked by `parent_uuid`:

```
prod-debug (uuid-1, parent=null) → sealed
  └── prod-debug-2 (uuid-2, parent=uuid-1) → sealed
       └── prod-debug-3 (uuid-3, parent=uuid-2) → running
```

`ads list` shows the **root session name** with aggregate info:

```
NAME              STATUS    SEGMENTS  LAST ACTIVE          PROFILE
prod-debug        running   3         2026-06-06 12:00     production
k8s-migration     sealed    1         2026-06-05 18:45     default
local-dev         sealed    7         2026-06-04 09:30     dev
```

`ads search` searches across ALL sessions in a family and labels
results with the root name.

`ads delete prod-debug` deletes the entire family (all linked `.db`
files + all `meta.db` rows).

## 8. PTY Proxy Internals

```go
// internal/pty/proxy.go — simplified pseudocode

func Run(sessionUUID string, db *sessiondb.DB) error {
    // 1. Start bash on a new PTY
    shell := exec.Command("/bin/bash", "--rcfile", oscHooksFile())
    ptmx, _ := pty.Start(shell)
    defer ptmx.Close()

    // 2. Set raw mode on outer terminal
    oldState, _ := term.MakeRaw(int(os.Stdin.Fd()))
    defer term.Restore(int(os.Stdin.Fd()), oldState)

    // 3. Signal handling
    sigCh := make(chan os.Signal, 1)
    signal.Notify(sigCh, syscall.SIGWINCH, syscall.SIGTERM, syscall.SIGHUP)
    go func() {
        for sig := range sigCh {
            switch sig {
            case syscall.SIGWINCH:
                pty.InheritSize(os.Stdin, ptmx)
            case syscall.SIGTERM, syscall.SIGHUP:
                shell.Process.Signal(syscall.SIGTERM)
            }
        }
    }()
    pty.InheritSize(os.Stdin, ptmx) // initial size

    // 4. Buffered writer (batches commits)
    writer := sessiondb.NewBufferedWriter(db, 64*1024, 100*time.Millisecond)
    defer writer.Flush()

    scanner := ansi.NewOSCScanner(db)

    // 5. Bidirectional copy
    ctx, cancel := context.WithCancel(context.Background())
    defer cancel()

    // Input: user → bash (and record)
    go func() {
        buf := make([]byte, 4096)
        for {
            n, err := os.Stdin.Read(buf)
            if n > 0 {
                ptmx.Write(buf[:n])
                writer.WriteInput(buf[:n])
            }
            if err != nil { cancel(); return }
        }
    }()

    // Output: bash → user (and record + parse)
    buf := make([]byte, 4096)
    for {
        n, err := ptmx.Read(buf)
        if n > 0 {
            os.Stdout.Write(buf[:n])
            writer.WriteOutput(buf[:n])
            scanner.Write(buf[:n])
        }
        if err != nil { break }
    }

    return shell.Wait()
}
```

### Buffered Writer

Commits to SQLite every 100ms or 64KB, whichever comes first. Prevents
transaction-per-chunk overhead during high throughput (e.g., `cat
large_file`).

```go
type BufferedWriter struct {
    db        *DB
    outBuf    []byte
    inBuf     []byte
    mu        sync.Mutex
    ticker    *time.Ticker
    maxBytes  int
}
```

### Tab Launch

`ads run <name>` opens a Konsole tab:

```go
// internal/konsole/dbus.go
func OpenTab(sessionUUID string) error {
    cmd := exec.Command("konsole", "--new-tab",
        "-e", "ads-shell", "--session", sessionUUID)
    if err := cmd.Start(); err != nil {
        return err
    }
    return cmd.Process.Release()
}
```

Fallback when no display is available:

```go
func (r *Runner) Launch(uuid string) {
    if hasDisplay() {
        konsole.OpenTab(uuid)
    } else {
        syscall.Exec(adsShellBin, []string{"ads-shell", "--session", uuid}, os.Environ())
    }
}
```

## 10. Migration from v3.x

### What Users Need to Do

1. Install new binaries (`make install`)
2. Run `ads konsole install` to set up the Konsole profile
3. Existing `meta.db` will be auto-migrated (new columns added, tmux columns ignored)
4. Existing session `.db` files remain searchable (read-only compatible)
5. tmux is no longer required (but won't conflict if installed)

### Schema Migration

```sql
-- Auto-applied on first meta.Open()
ALTER TABLE sessions ADD COLUMN parent_uuid TEXT;
ALTER TABLE sessions ADD COLUMN sealed_at DATETIME;
-- Old columns (remote_user, remote_host, remote_port, type) left in place, ignored
-- tmux_profiles table left in place, ignored
-- plugin_configs renamed/migrated to llm_config
```
